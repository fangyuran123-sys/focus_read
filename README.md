# Kindle Desk

本地优先的个人图书馆：在电脑保存和整理图书，通过 USB 发送到 Kindle，并归档阅读摘录。无需账号，页面和数据都保存在本机，运行时无需联网。

## 桌面与个人图书馆（源码预览版）

这部分为新增源码功能；下文发布的 **0.2.0 离线镜像不包含这些改动**。使用源码运行，或按下文方式重新构建镜像。

Linux 桌面需要 Python **3.11+**、systemd 用户会话。完整桌面窗口使用 PyQt6 + Qt WebEngine（Debian/Ubuntu 系统包 `python3-pyqt6.qtwebengine`），未安装时回退为 Chrome/Chromium 的仅图书馆窗口，不包含内置找书。Kindle 与本地图书馆基础功能无需 Python/npm 第三方包；补封面使用系统 `python3-pil` 和 calibre，墨案 MTP 发送另需系统 `python3-gi`（见下文）：

```sh
python3 desktop.py --install   # 安装当前用户的应用菜单入口，只需执行一次
python3 desktop.py             # 启动独立应用窗口；也可以从应用菜单打开 Kindle Desk
```

Qt 窗口提供“我的图书馆 / 找书（Z-Library）/ 下载管理 / 封面与壁纸”侧栏，复用现有本机 HTTP 服务；不是跨平台安装包。图书馆页面不需要网络，找书网页需要网络。源码目录移动后需重新安装菜单入口。

### 内置找书与下载（Qt 桌面版）

1. 点击桌面侧栏“找书 / Z-Library”，输入自己核实过的公共 **HTTPS** 书源地址。应用不预置 Z-Library 镜像、不保存账号密码、不提供非官方 API 插件或爬虫；登录、验证码与下载权限按网站正常流程操作，仅下载你有权获取的内容。
2. 网站加载后可前进/后退/刷新；点“设为书源首页”保存当前地址（去掉查询参数/片段，不把登录 URL 中的 token 持久化为书源）。这是原网站独立网页，不是 iframe，不重排第三方网站界面。
3. 下载仅接收 EPUB、PDF、AZW/AZW3、MOBI、PRC、TXT，单本上限 200 MiB。网站下载完成后进入“下载管理”，点击“加入书库”并确认。格式头校验会拦截改名的 HTML 登录页、错误页、损坏 EPUB 等；这不是恶意文件扫描，图书内容仍需信任来源。
4. 本机路径为 `~/.local/share/kindle-desk/qt/downloads/<唯一ID>/<文件名>`（尊重 `XDG_DATA_HOME`）。每次下载使用独立目录，不覆盖同名文件；未完成内容保留为 `.part`，不提供入库。重启可找回完成的下载并重试入库。入库按内容去重、沿用原有复制导入：**下载原件仍保留**，不会自动移动/删除或发送到阅读器。
5. 本机图书馆与外部网站使用独立的 Qt profiles/Cookie 存储；不暴露原生桥接或路径导入 HTTP 接口给网站。网站页面禁止文件上传/文件系统授权/摄像头等权限，并拦截本机、私网、非 HTTPS 导航和请求；图书馆页面只访问 `127.0.0.1:8765`。不忽略 TLS 证书错误，不关闭 Chromium sandbox。网络拦截属于应用层边界，不等同于操作系统级网络沙箱，浏览器运行库仍需保持更新。

Qt profiles 存在 `~/.local/share/kindle-desk/qt/library` 与 `websites`，登录 Cookie/网站存储可能留在本机，不要共享或提交这些目录。正常退出会等待导入完成；有下载任务时先确认取消。原 Chrome profile 不会自动迁移到 Qt，网站需重新登录。某些反自动化/DRM/弹窗登录流程可能不兼容；新窗口请求在当前网页打开，文件上传被禁用，不承诺所有书源可用。普通浏览器访问 `8765`、Docker 模式仍只有原有图书馆功能。

没有已验证的 Z-Library 官方 API，因此先实现通用浏览器下载，不编造搜索/登录/下载接口。要做无原站 UI 的书源插件，需要后续提供合法可用且已核实的 API 文档与认证方式。

### 内置封面 / 壁纸（InkPaper）

桌面侧栏“封面 / 壁纸”默认打开用户指定的 <https://inkpaper.foolstack.net/>，使用第三个独立 browser profile，与找书和本地图书馆隔离，保留原站界面。不爬取图库、不猜 API，不自动更换任何设备壁纸。

- 在站内浏览、点 Download，原站的 HTTPS / Blob 图片下载会进入同一个下载管理器。此入口只接收单帧 JPEG/PNG（8 MiB、2000 万像素以内），实际图片解码校验，拒绝 HTML、SVG、可执行文件和损坏图片。找书入口仍只接收电子书，不因图片功能而放开网站文件权限。
- 下载完成后点“预览 / 用作封面”，搜索本地图书并选择具体文件，确认直接更新所选书库文件，不新增文件条目。EPUB、AZW3、MOBI 保持格式；TXT/AZW 需额外确认转换并替换为 AZW3，不再保留书库内旧格式。沿用现有补封面服务，不改下载源文件，也不自动发送。图片保留在下载目录，重启仍可找到，若只是做壁纸也可直接使用该文件。
- 选择书籍时只显示搜索前 36 本，可用关键词缩小范围；按图书 ID/文件 ID 指定目标，不按书名猜测归属。没有确认或取消对话框不会改封面。书库搜索/选书为本机原生界面，网站没有调用本机接口的桥接。
- 图片原样保存，不自动裁切或适配屏幕。墨案锁屏图还需转换成合适的 PNG（EPD105 推荐 720×1280）并通过原厂菜单选择；Kindle 需开启“显示封面”并传入、阅读更新后的图书。第三方图库可用性与图片使用授权以原站为准，仍可能因网络或站点变化失败。

关闭窗口不会停止后台服务，停止仍用 `systemctl --user stop kindle-desk`。不需要独立窗口时，也可执行 `./start.sh` 后访问 <http://127.0.0.1:8765>。

### 墨案迷你阅（EPD105）接入

Linux 本机版新增侧栏 **“墨案设备”**，与 Kindle 设备书架、阅读日历分开。实机验证为 USB `1f3a:1006`、MTP 标识 `Allwinner EPD105`：

1. 在墨案选择“文件传输”，保持解锁；在桌面文件管理器打开 EPD105 的内部存储。
2. 打开应用“墨案设备”，点击“刷新墨案”。只识别当前 Linux 用户已有的 GVfs MTP 挂载；不自动挂载其他手机。多台 EPD105 同时连接时拒绝选择，避免发错设备。
3. 墨案页沿用 Kindle 的双栏设备布局：左侧为设备预览、连接状态、真实 MTP 可用容量（设备/GIO 未提供时显示“—”）；右侧为阅读积累、传书、传输记录和设备书架。逐级进入 `Books`、`小说` 等目录，查看图书、下载原文件或“导入本地书库”。支持在当前目录新建分类，存在同名文件/目录时拒绝创建。一次只扫描当前目录，不爬取应用缓存；不访问隐藏目录或 `Android` 数据。复制导入上限 200 MiB，沿用哈希去重，不改墨案原文件。
4. 先在墨案页选好目标书籍目录，可以直接拖入/选择多个文件并点 **“传入墨案”**，也可以到本地图书详情点 **“发送墨案”**，确认显示的目标目录。批量传输遇到单个失败会继续，最终逐项提示失败原因，最近 8 条校验成功记录保存在本机。支持 EPUB、PDF、TXT，单本不超过 200 MiB，EPUB 不转换；通过 GIO 的禁止覆盖复制发送，再读回做 SHA-256 校验。同名文件拒绝覆盖，失败会提示；可能残留的失败副本需在设备上检查。发送需要系统 `python3-gi`（GIO，桌面发行版通常已有），缺少时可下载后手动复制，不会静默使用可覆盖的 `gio copy` 命令。

**阅读统计调查与限制：**设备/阅读 App 可能有阅读时长，不等于 MTP 会暴露它的数据库。已只读检查多看与 MiReader 的外部目录、缓存、诊断文件及可见数据库：`DuoKan/Downloads/Cloud/*/resources.vfs` 是书籍资源索引，掌阅的 `books/.idea/idea.db` 是评论/想法缓存，不是每日阅读时长；没有发现可验证的会话/每日时长表。当前暂不自动导入墨案摘录或生成墨案时长热力图，不拿文件访问时间或诊断日志冒充阅读。需要用户提供设备内统计页面对应的阅读 App、导出样例或在用户明确授权后另行调查的数据接口，才能继续接入。Kindle 历史不变。

MTP 操作能力与磁盘不同，不提供墨案设备端移动/删除/应用内弹出；用系统文件管理器断开，传输完成前不要拔线。不要求 ADB、root 或修改固件，统一了页面布局不代表底层能力完全相同。

此功能依赖宿主机用户会话的 GVfs/MTP，不支持现有 Docker 部署中的 MTP 转发；容器仍使用原有 Kindle 磁盘挂载。

### 个人图书馆能做什么

- **离线导入**：支持 EPUB、PDF、AZW3、AZW、MOBI、TXT、KFX、PRC，单文件不超过 200 MiB。复制文件到 `data/library/`，不移动、不修改源文件；完全相同的文件按 SHA-256 去重。批量导入遇到单个失败会继续处理其余文件，最后列出失败文件和原因。
- **管理书籍**：搜索书名/作者（按 `/` 直接跳到搜索框），按标签和想读/在读/已读/搁置筛选，可按最近添加、书名、作者或评分从高到低排序，并按最低星级筛选；列表每页 36 本，只有一页时不显示翻页。
- **进度与评分**：详情中手动保存 0–100% 的进度、当前页码及 1–5 星评分（可清除评分），在读书籍显示进度条；标记已读时进度设为 100%。页码与百分比独立记录，不与 Kindle 同步。
- **阅读日历**：侧栏“阅读日历”以年度热力图展示已导入的 Kindle 阅读会话时长；按周排列，颜色分为不足 15 分钟、15–30 分钟、30–60 分钟和至少 60 分钟，点击日期或用方向键查看当天时长。连接 Kindle 后点击“刷新设备”导入，重复刷新不累加，断开设备或设备缓存清空后仍保留本地历史。统计独立于本地图书，删除本地图书不会删日历。
  - 实机验证：Kindle 第 11 代（2022）、固件 5.19.2.0.1，读取 `system/fmcache/fmcache.db` 的 `reading_sessions.session`（schema version 0），复制数据库及 WAL/SHM 到本机临时目录后只读解析，不修改设备。仅归档已结束且时间有效的会话，不保存书籍标题或原始遥测事件。
  - **口径限制**：是设备记录的会话起止时长，不是经过验证的专注阅读时间，可能包含停留或调设置；不把位置差换算成页数。重叠会话去重后按服务器/电脑本地时区在午夜拆分（包含夏令时）。设备时钟错误、固件变化或缓存清理会使记录不完整；空格表示无已导入记录，不能推断当天没读。未知结构/无效会话会提示，不用摘录日期或文件修改时间冒充阅读时长。没有历史的年份显示空日历，不生成示例数据。
- **阅读记录与暖光**：侧栏显示今年读完、累计已读、正在阅读及归档摘录数量，统计不受搜索/筛选影响。今年读完只计算本版本记录了完成日期且当前为已读的书；旧已读书籍不推测日期，移回在读会清除完成日期，再标记已读按新日期计算。暖光滑块调节界面纸面的冷暖，保存在当前浏览器；不支持 CSS `color-mix()` 的旧浏览器保持默认纸色。
- **删除图书**：详情底部打开二次确认，默认只移出书库并保留本地文件，可勾选同时清理所有格式和转换副本。书籍信息、进度、评分、阅读笔记及封面缓存随书籍移除，不可撤销；不删除导入源文件、Kindle 副本或归档摘录。保留的文件不在书库显示，重新导入源文件可再次加入（不会恢复已删除的书籍信息）；如果文件清理失败，会明确提示残留文件。
- **补封面（本地更新）**：本地图书详情的“文件与设备”中，可对 EPUB、AZW3、AZW、MOBI、TXT 点击“上传封面”或“生成文字封面”。上传限单帧 JPEG/PNG、8 MiB、2000 万像素；文字版使用已保存的书名和作者，先保存信息再操作。EPUB 在临时副本上用 calibre 更新元数据；AZW3/MOBI 重新生成同格式文件（直接改元数据可能无法补上缺失的内嵌封面），保持文件 ID，不新增版本。TXT 不能内嵌封面、旧 AZW 需转换，额外确认后将同一文件条目替换为 AZW3，书库内不再保留旧格式。重新提取并校验封面后，先保存新内容，再提交数据库引用，成功后清理所选旧文件和已识别的 EPUB 发送转换缓存；失败保留旧引用/旧封面，清理失败明确提示，不新增 `cover-*.azw3` 文件条目。下载源文件、设备旧文件不变，既有历史补封面版本和用户手动添加的格式不批量删除。内容若与其他条目冲突则拒绝替换，不自动合并。上传图片去除元数据并转 JPEG，预览同步刷新；发送 EPUB 会按更新后的内容重新转换。
  - 运行需要 calibre（`ebook-convert`、`ebook-meta`）、Pillow（系统包 `python3-pil`），自动中文封面还需 `fonts-noto-cjk`。Docker 构建已包含，现成 0.2.0 镜像需重建；本机缺依赖会提示。测试也需要 Pillow。
  - 仅支持未加密图书；PDF/KFX/PRC 暂不开放，不能绕过 DRM。更新会替换书库文件，操作前应备份 `data/`；TXT/AZW 转换和 AZW3/MOBI 重建可能改变排版/编码，需先测试一本。进程若在提交与清理之间中断，可能留下不被引用的旧文件，但不先删除仍被引用的原文件。Kindle 上已有的旧书不会自动更新，同名传输仍拒绝覆盖，不自动迁移设备端进度与标注。锁屏封面依赖 Kindle 的显示封面设置及识别，不能保证每本书立即显示；先拿一本验证。此版本只提供单本操作，不会自动改整个书库。
- **封面**：导入时提取文件内嵌封面，缓存在 `data/covers/`；仅当 EPUB 包内声明了封面才提取，避免把正文第一页当封面。没有封面的书（TXT、多数 PDF、未声明封面的 EPUB）显示排版生成的封面，可随时手动修改书名。
- **详情与笔记**：编辑书名、作者、简介、标签、阅读状态和阅读笔记。安装 calibre 后，新书导入时自动读取 EPUB、PDF、AZW、AZW3、MOBI、PRC 内嵌的书名和作者（不联网）；读取失败或超时仍按文件名保存，并提示手动编辑。TXT/KFX、未安装工具时直接使用文件名。已有书籍、重复导入及添加格式不会覆盖手工信息；没有可用内嵌封面时使用排版占位。
- **多格式**：详情中添加其他格式，关联到同一本书；不同译本或版本建议分别建书。不会按标题自动合并书籍；已经独立导入的两本书暂不提供合并入口。
- **下载与传书**：离线下载原文件；连接 Kindle 后选择目录发送。EPUB 转换副本保存在本地、关联到原书，原始 EPUB 永久保留并复用已转换文件。KFX、PRC 目前仅本地保存和下载，不开放发送入口。
- **原有功能保留**：侧栏“阅读摘录”和“Kindle 设备”打开现有工具。设备书架仍是快照，设备上的书不会自动复制进本地图书馆。需保存时，下载原文件后导入。

本地图书和文件有独立稳定 ID，修改元数据不会改名或移动底层文件。文件按内容哈希保存，请勿手工重命名 `data/library/` 内容。发送时间/路径只是历史记录，不代表设备副本仍在原处；不自动同步阅读进度，也不把摘录按同名自动关联。

**备份：**先停止服务，再备份完整 `data/`（包含 `desk.sqlite3`、`library/` 和 `covers/`），不要只备份数据库。恢复到新目录后，可用 `python3 server.py --data /恢复/data` 验证书籍及文件下载。现有数据库会自动增加图书库表，不删除旧摘录或设备快照；首次升级前仍应备份。当前不提供联网抓取元数据、在线阅读器或云同步。

以下为 **0.2.0 发布版**的设备管理与部署说明。当前发布版本 **0.2.0**。主要使用环境是 Linux 主机或 Linux 虚拟机，现有设备为 Kindle 第 11 代（2022），固件 5.19.2.0.1。发布镜像为 **Linux amd64**；其他设备、架构和操作系统没有完整验证。

| 可以做什么 | 当前行为 |
| --- | --- |
| 查看书架 | 读取设备图书、所在文件夹和存储空间；断开后保留最近一次书架 |
| 文件夹分类 | 新建分类、子分类，按目录筛选，将单本书籍和识别到的关联附件一起移动 |
| 传入图书 | EPUB 在本地转为 AZW3；PDF、AZW3、AZW、MOBI、TXT 直接复制 |
| 归档摘录 | 导入中英文 `My Clippings.txt`，读取部分设备标注数据库内容，搜索和筛选 |
| 导出与备份 | 摘录导出为 Markdown ZIP，一本书一个文件；下载单本原始书籍文件 |

**分类对应 Kindle 磁盘上的真实文件夹，不会自动成为 Kindle 屏幕上的收藏集。** 本应用不破解 DRM，也不修改 Kindle 固件。

## 1. 选择运行方式

| 方式 | 适合场景 | 主机需要准备 |
| --- | --- | --- |
| Docker 离线包（推荐） | 换电脑部署、避免安装应用依赖 | 本地 Linux Docker Engine、Docker Compose、Bash、`mountpoint` |
| 从源码构建 Docker 镜像 | 修改代码后部署 | 上述环境、源码，以及构建时的网络访问 |
| Linux 本机运行 | 本机开发、使用网页中的安全弹出 | Python 3.11+；后台启动另需 systemd 用户会话；EPUB 转换另需 calibre |

Docker 镜像已经包含 Python、calibre 和中文字体，目标主机无需安装这些软件，也无需 Node.js、npm 或应用源码。但 USB 和文件权限仍由主机管理：

- Kindle 必须先被识别为磁盘并挂载，挂载点下有 `documents/`，当前用户能读写它。本版没有 MTP 连接适配。
- 使用虚拟机时，先将 USB 设备连接到该虚拟机，再在虚拟机里挂载。
- Docker 服务必须在设备所在的 Linux 主机上运行。这里不支持通过远程 Docker daemon 读取客户端本地 USB。
- Windows/macOS Docker Desktop 的设备共享和文件移动行为尚未验证，不能仅凭安装了 Docker 就认定可用。

默认地址是 <http://127.0.0.1:8765>，应在**运行服务的那台系统**的浏览器里打开。Linux 虚拟机中的 `127.0.0.1` 不等于 Windows 主机中的 `127.0.0.1`。

## 2. Docker 快速开始

### 准备设备

用系统文件管理器挂载 Kindle，并确认路径。例如本机使用 `/run/media/rose/Kindle`，其他机器以实际路径为准。

```sh
docker info
docker compose version
findmnt --mountpoint "/实际/Kindle挂载点"
ls "/实际/Kindle挂载点/documents"
```

后文的 `/实际/Kindle挂载点` 都需要替换。应传入 **Kindle 根挂载点**，不要传入它的 `documents` 子目录。

如果此前使用 `start.sh` 启动了本机版，先停止它，再启动容器，避免占用同一端口和数据目录：

```sh
systemctl --user stop kindle-desk
```

### 方式 A：使用离线部署包

发布包名为 `kindle-desk-0.2.0-linux-amd64-bundle.tar.gz`，本项目生成的包位于 `dist/`。将它复制到目标 Linux amd64 主机：

```sh
tar -xzf kindle-desk-0.2.0-linux-amd64-bundle.tar.gz
cd kindle-desk-0.2.0-linux-amd64
sha256sum -c SHA256SUMS
docker load -i kindle-desk-0.2.0-linux-amd64.tar.gz
./docker-start.sh "/实际/Kindle挂载点"
```

校验通过并启动成功后，打开 <http://127.0.0.1:8765>。这里的 `docker load` 读取本地镜像文件，启动过程不会拉取镜像或下载转换工具。完整部署包不包含你的图书、摘录或本机 `.env`。

包内文件：

| 文件 | 用途 |
| --- | --- |
| `kindle-desk-0.2.0-linux-amd64.tar.gz` | 供 `docker load` 载入的镜像；它与外层部署包是两个文件 |
| `docker-start.sh`、`compose.yaml` | 启动脚本及容器配置 |
| `README.md`、`.env.example` | 使用说明及手动 Compose 配置示例 |
| `BUILD.txt`、`SHA256SUMS` | 镜像版本、源码提交和文件校验值 |

### 方式 B：在源码目录构建

首次构建需要联网获取 Debian 基础镜像和软件包，构建完成后可离线运行。在含 `Dockerfile` 的源码目录执行：

```sh
docker build --build-arg VERSION=0.2.0 --build-arg VCS_REF="$(git rev-parse HEAD)" -t kindle-desk:0.2.0 .
./docker-start.sh "/实际/Kindle挂载点"
```

若本机已经有 `kindle-desk:0.2.0`，可以直接执行启动脚本。其他 CPU 架构需单独构建、验证；当前离线包不能视为多架构镜像。

### 启动脚本会做什么

`docker-start.sh` 检查挂载点、`documents/` 读写权限、Docker 和本地镜像，使用当前用户的 UID/GID，自动创建部署目录下的 `data/`，然后等待容器健康检查通过。重复运行会**重新创建容器**，以接入当前 USB 挂载；数据目录保留。

脚本不读取 `.env`。自定义数据位置或镜像时，显式传入环境变量：

```sh
KINDLE_DATA="/绝对路径/已有data" KINDLE_IMAGE=kindle-desk:0.2.0 ./docker-start.sh "/实际/Kindle挂载点"
```

`KINDLE_DATA` 默认是脚本目录下的 `data/`；相对路径也以脚本目录为基准。建议使用绝对路径，便于升级时继续使用同一份数据。不要用 `sudo` 启动脚本；应让当前用户有 Docker 使用权限和设备写入权限。

### 日常启停和重新连接

以下命令在包含 `compose.yaml` 的部署目录执行：

```sh
# 查看状态、跟踪日志；退出日志查看不会停止容器。
KINDLE_MOUNT="/实际/Kindle挂载点" docker compose ps
KINDLE_MOUNT="/实际/Kindle挂载点" docker compose logs --tail=100 -f

# 拔线前先停止并移除容器，再从宿主机文件管理器安全弹出。
KINDLE_MOUNT="/实际/Kindle挂载点" docker compose down

# 重新插入并挂载后，再运行启动脚本。
./docker-start.sh "/实际/Kindle挂载点"
```

单个设备目录通过 bind mount 传入容器。设备重新挂载后需要重建容器，单纯刷新网页或重启旧容器不能代替这一步。容器内的“安全弹出”按钮会禁用。

关闭终端不会停止容器；本项目没有配置开机自启，重启主机后应先挂载 Kindle，再运行启动脚本。

### 手动 Compose 配置（可选）

如果希望通过 `.env` 固定配置，可直接使用 Compose：

```sh
cp .env.example .env
id -u
id -g
# 编辑 .env，填入实际挂载路径、上面两项 ID 和数据目录。
mkdir -p data
# 确保镜像已载入或构建，数据目录存在且可写。
docker compose up -d --force-recreate --wait
```

不要覆盖已有 `.env`；首次创建后再编辑。若设置了其他 `KINDLE_DATA`，需要事先创建那个目录。

| 配置项 | 含义 |
| --- | --- |
| `KINDLE_MOUNT` | 宿主机的 Kindle 根挂载点，必须已存在 |
| `LOCAL_UID` / `LOCAL_GID` | 手动 Compose 使用的用户身份，应与设备和数据目录权限匹配 |
| `KINDLE_DATA` | 本地数据目录，默认 `./data` |
| `KINDLE_IMAGE` | 已载入或构建的镜像，当前为 `kindle-desk:0.2.0` |

手动 Compose 会读取 `.env`；`docker-start.sh` 使用参数和环境变量，两种入口不要混淆。旧配置升级到本版时，需要更新 `.env` 中的镜像版本。Compose 不自动构建，也不自动拉取镜像。

容器以普通用户运行，根文件系统只读，只开放设备与数据目录的必要写入，不使用 privileged。端口只发布到 `127.0.0.1:8765`，Host、Origin 和操作令牌校验仍生效；请保持映射两端均为 8765。当前没有面向公网或局域网多用户访问的登录机制。

## 3. 使用图书和摘录管理

### 文件夹分类

1. 在“设备书架”选择“新建分类”，填写单个目录名称并选择上级目录。例如先在根目录创建“文学”，再以“文学”为上级创建“散文”。
2. 从分类下拉框筛选图书。每项显示该目录**直接包含**的书籍，子目录单独列出。
3. 点击书籍旁的“移动”，选择目标分类。也可以把书移回根目录。

上述操作直接修改 Kindle 的 `documents/`。例如 `文学/散文` 对应 `documents/文学/散文`。已有目录和空目录也会显示，断开后可查看最近一次读取的结构。

移动保持书籍文件名不变，并一起移动识别到的同名 `.sdr` 目录及 `.mbp`、`.mbp1`、`.mbs`、`.pdr`、`.apnx`、`.phl` 附件。遇到目标重名，或同名多格式书籍共用附件时会拒绝移动，避免覆盖或拆散文件。

### 传入图书

拖入文件或点击上传区域，选择“传入分类”，然后点击“传入 Kindle”。可选择多个文件，逐本处理；单文件上限为 200 MiB。

- EPUB 使用 calibre 本地转换为 AZW3，转换需要一些时间。
- PDF、AZW3、AZW、MOBI、TXT 直接复制。
- 默认目的地为 `documents/Kindle Desk`，可改成已有分类；同名文件不会覆盖。
- “已复制”表示文件写入完成。整理完后安全弹出，等待 Kindle 更新书架并自行验证能否打开。

“备份文件”下载原始书籍本体，不会去除 DRM，也不包含整个 `.sdr` 附件目录。需要完整设备备份时，应另行复制书籍和配套文件。

### 阅读摘录

连接后点击“刷新设备”，程序读取 `My Clippings.txt` / `我的剪贴.txt`，并尝试读取 `ksdk_annotation_v1.db` 中可识别的内容。也可以点击“导入摘录”手动导入剪贴文件；同一来源中已识别的记录会去重。

使用搜索框、书名筛选和“只看新增”查看摘录。“导出全部”生成 Markdown ZIP，一本书一个文件，解压后可放入 Obsidian。

部分新版标注数据库只保存高亮位置，页面会显示“正文尚未解析”。这是当前解析能力的限制，不代表一定没有高亮。程序先复制设备数据库再读取，不回写设备标注库；已归档记录不会跟随设备端删除。

## 4. 数据、备份与升级

图书保存在 Kindle 上，应用数据保存在宿主机。默认结构如下：

```text
data/
├── desk.sqlite3     # 摘录、离线书架、传输记录和导出状态
├── library/        # 源码预览版：本地图书原文件和转换副本
├── covers/         # 源码预览版：从图书提取的封面（没有就没有）
├── backups/        # 扫描设备时备份的剪贴文件原件
├── moves/          # 未完成移动的位置记录；成功后移除对应记录
└── calibre-config/ # 转换工具生成的配置（使用后可能出现）
```

`docker compose down`、重建容器和更新镜像都不会删除这个宿主机目录。删除它会丢失本地归档；只备份它也不能备份 Kindle 图书本体。

备份前先停止使用该目录的实例。对于默认 `data/`，在部署目录执行：

```sh
KINDLE_MOUNT="/实际/Kindle挂载点" docker compose down
# 本机版用户则先执行：systemctl --user stop kindle-desk
tar -czf "kindle-data-$(date +%Y%m%d-%H%M%S).tar.gz" data
```

升级或换电脑时，先备份，再导入新镜像，并将**完整数据目录**复制或保留在稳定位置。新部署通过 `KINDLE_DATA` 指向它。恢复备份时先解压到新目录，确认结构后使用；不要让两个实例同时操作同一份数据或设备。

### 移动中断后的处理

多个文件无法在一次原子操作中一起移动。程序会先把原位置和目标位置写入 `data/moves/*.json`；普通失败会尝试回退。若拔线、断电等导致回退失败，记录保留，后续移动被阻止。

出现此提示时，先停止整理并停止应用，重新连接设备，备份涉及的书籍和附件。根据记录中的 `from`、`to` 核对两端，确认文件完整、书籍和附件已在同一目录，且不存在未处理的冲突后，才能清除对应恢复记录并继续。Docker 记录中的 `/kindle` 对应宿主机设置的挂载点；记录本身不包含文件副本。

## 5. Linux 本机运行

在源码目录执行：

```sh
./start.sh
```

脚本需要 Python 3、`systemctl`、`systemd-run`，会启动当前用户的后台服务。重复执行复用已运行实例；关闭终端不会停止服务，重启系统后需重新执行。

```sh
systemctl --user status kindle-desk
journalctl --user -u kindle-desk -n 30 --no-pager
systemctl --user restart kindle-desk
systemctl --user stop kindle-desk
```

默认设备路径是 `/run/media/rose/Kindle`，地址是 <http://127.0.0.1:8765>。自定义路径、端口或数据目录时，先停止已有实例，再以前台方式运行：

```sh
systemctl --user stop kindle-desk
python3 server.py --mount "/实际/Kindle挂载点" --port 8766 --data "/绝对路径/data"
```

此时访问 <http://127.0.0.1:8766>，Ctrl+C 停止。无需 systemd 的环境也可直接运行这个 Python 命令。

本机版的 EPUB 转换需要额外准备 calibre。程序优先使用 `--converter` 指定的路径或 `PATH` 中的 `ebook-convert`，也会查找项目内的 `runtime/calibre/ebook-convert`。本机已有的 `runtime/` 不属于 Git 源码，复制或检出源码不会自动携带转换工具。未安装 calibre 时仍可直接传入其他支持格式。

本机版“安全弹出”依赖宿主机的 `findmnt` 和 `udisksctl`；如果无法确认设备或卸载失败，使用系统文件管理器弹出。

## 6. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 提示“Kindle 尚未挂载” | 用文件管理器挂载，确认传的是设备根挂载点而非 `documents/`；虚拟机先检查 USB 是否已交给它 |
| 找不到镜像 | 先对包内镜像执行 `docker load -i`，或在源码目录构建；外层 `*-bundle.tar.gz` 应先用 `tar` 解压 |
| 无法写入设备或数据目录 | 检查主机挂载是否只读、目录权限及 UID/GID；容器不会自动修复主机权限 |
| 提示本机版仍在运行或端口占用 | 停止自己启动的旧实例；查看 `systemctl --user status kindle-desk` 和 `docker ps`，不要同时启动两种方式 |
| 重新插入后仍看不到书 | Docker 用户先挂载，再重跑 `docker-start.sh`；本机用户确认路径后点击“刷新设备” |
| 容器健康但网页显示未连接 | 健康检查只说明服务接口可用，不保证 USB、图书扫描或写入成功；检查挂载及页面提示 |
| Windows 浏览器打不开虚拟机的 localhost | 在 Linux 虚拟机内打开该地址；默认没有对外开放访问 |
| EPUB 转换失败 | Docker 用户查看容器日志；本机用户检查 calibre 路径；同时确认文件完整、未加密及磁盘空间充足 |
| 高亮没有正文 | 新版数据库可能只有位置信息；尝试导入含正文的 `My Clippings.txt`，详见已知限制 |
| 提示未完成的移动记录 | 按上面的恢复流程检查实际文件，不要直接清空 `data/moves/` 来跳过检查 |

## 7. 已知限制

- 文件夹分类服务于本网页和磁盘整理，不生成 Kindle 收藏集；分类目前支持新建和移动单本书籍，没有分类重命名、删除或批量移动入口。
- 设备移动后的重索引、阅读进度和不同 KFX 附件关联未作完整实机验证。
- 数据库标注解析不完整，不认识的本地编辑操作会提示并保留旧记录；剪贴文件和数据库的位置体系不同，不跨来源自动合并去重。
- 电量、阅读百分比、当前阅读页面未实现。设备预览不代表正在阅读的书；界面中的型号和固件信息目前针对现有设备配置，不是通用设备探测结果。
- 下载原始书籍不等于移除 DRM，也不保证能在其他阅读器打开。
- Windows 原生启动、MTP 适配、Windows/macOS Docker Desktop 和其他 CPU 架构尚未验证或实现。

## 8. 开发与验证

后端为 Python 3.11+ 标准库 HTTP 服务和 SQLite，前端为静态 HTML/CSS/JavaScript，无需 npm 构建。主要文件：

| `desktop_browser.py` / `desktop_downloads.py` | 隔离网页浏览、下载管理和原生确认入库 |
| `web/` | 本地图书馆和设备管理页面 |
| `start.sh` / `docker-start.sh` | 本机服务启动 / Docker 启动 |
| `Dockerfile` / `compose.yaml` | 镜像构建 / 运行配置 |
| `test_server.py` / `test_docker_start.py` / `test_library.py` / `test_desktop.py` | 后端、启动、图书库及桌面入口测试 |
| `check_docker.py` | 独立容器集成验证 |

```sh
python3 -m unittest -v test_server.py test_docker_start.py
# 先构建 0.2.0 镜像，再执行容器验证；测试需要主机 Python 和 Docker。
python3 check_docker.py
```

测试使用临时目录模拟设备；容器测试使用独立 Compose 项目和随机本机端口，退出时清理测试容器。0.2.0 已通过 21 项单元测试，以及实际 EPUB 转换、文件夹移动、附件保留和重建后数据保留的容器验证；这些结果不能替代真机阅读验证。

镜像不包含 `data/`、`runtime/`、本机 `.env`、Git 历史或测试文件。镜像 OCI 标签和 `BUILD.txt` 的 Git commit 对应应用源码；离线包若另有 Documentation commit，则对应包内说明文档的提交。
